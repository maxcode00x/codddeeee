# Полевой помощник наладчика ПЛК

Офлайн-первое PWA-приложение для наладчика ПЛК: журнал неисправностей,
таблица I/O с импортом CSV и экспортом протокола в PDF, список замечаний
(punch list) с приоритетами, паспорт оборудования, реестр версий проектов
с проверкой перед выездом на объект, инженерные калькуляторы,
офлайн-справочник по пяти томам курса «ПЛК от новичка до профи». Работает
без интернета, все данные — в IndexedDB на устройстве.

Реализованы этапы 1 и 2 из ТЗ: модули 1 (журнал), 2 (I/O), 3 (замечания),
4 (калькуляторы), 5 (паспорт оборудования), 6 (реестр версий), 7
(справочник). Модуль 8 (мастер диагностики) и статистика — следующий этап.

## Стек

Vite + React + TypeScript + Tailwind CSS, Dexie.js (IndexedDB),
react-router-dom, fuse.js (поиск), papaparse (CSV), jsPDF (PDF),
vite-plugin-pwa (офлайн-кэш).

## Разработка

```bash
npm install
npm run dev        # локальный сервер с горячей перезагрузкой
npm run build       # продакшн-сборка в dist/
npx tsc --noEmit      # проверка типов
```

## Справочник (модуль 7)

Исходники пяти томов лежат в `tomes/*.html` (не редактируются руками —
это те же файлы, из которых собираются PDF-книги отдельным инструментом).
Скрипт разбирает их в JSON:

```bash
node scripts/build-reference.mjs
```

Результат — `src/reference-data/*.json`, коммитится в репозиторий (не
генерируется на лету в браузере). Перезапускай скрипт и коммить заново,
если тома обновятся.

## Калькуляторы (модуль 4)

Вся числовая логика — чистые функции в
`src/modules/calculators/formulas.ts`, без React/DOM. Проверяются
отдельным скриптом на известных примерах до того, как попадают в UI:

```bash
node --experimental-strip-types scripts/verify-formulas.mjs
```

При изменении формул — сначала правь и гоняй этот скрипт, потом
переноси в компонент.

## Объекты (линия → шкаф → устройство)

`src/modules/objects/` — общее дерево объектов (`db.objects`,
самоссылающийся `parentId`), переиспользуется модулями 3/5/6 через
`useObjectTree` (плоский список с отступами для выпадающих списков) и
`ObjectPicker` (выбрать существующий объект или создать новый прямо в
форме, без ухода на отдельный экран).

## Замечания (модуль 3)

`src/modules/punchlist/` — список пунктов с приоритетом (A/B/C), статусом
и привязкой к объекту. Открытые пункты приоритета A показывают счётчик
и баннер в самом модуле и красный бейдж в навигации на вкладке
«Замечания» — это единственное предупреждение, которое видно из любого
места приложения.

## Паспорт оборудования (модуль 5)

`src/modules/equipment/` — карточки устройств (CPU, станция I/O,
частотник, панель, коммутатор, …) с серийным номером, прошивкой,
PROFINET/PROFIBUS-адресацией и местом бэкапа; боковой список объектов для
фильтрации, поиск по артикулу/имени, кнопка «Скопировать конфигурацию
похожего устройства» для быстрого заполнения повторяющегося железа,
экспорт в PDF.

## Реестр версий проектов (модуль 6)

`src/modules/versions/` — история версий проекта по объектам (версия,
среда разработки, что изменено, кто изменил, где архив, отметка «сейчас в
контроллере») и отдельная вкладка «Проверка перед выездом на объект»
(`PreDepartureCheck.tsx`): сравнивает сохранённую локально версию твоей
среды разработки (`localStorage['pfa-my-env']`) с последней
зафиксированной версией на объекте и предупреждает при несовпадении, а
также если последняя запись о бэкапе старше 30 дней.

## Структура

```
src/
  db/schema.ts          # Dexie: таблицы и версии (v2: + punchList, equipment, projectVersions)
  lib/                    # search.ts (Fuse), csv.ts, pdf.ts — общие утилиты
  modules/
    calculators/            # модуль 4
    faultlog/                 # модуль 1
    io-table/                   # модуль 2
    objects/                      # дерево объектов, общее для 3/5/6
    punchlist/                      # модуль 3
    equipment/                        # модуль 5
    versions/                           # модуль 6
    reference/                            # модуль 7
  reference-data/                          # сгенерированный JSON из tomes/
scripts/
  build-reference.mjs                       # tomes/*.html -> reference-data/*.json
  verify-formulas.mjs                         # проверка калькуляторов
tomes/                                          # исходные HTML-тома + style_v2.css
```
