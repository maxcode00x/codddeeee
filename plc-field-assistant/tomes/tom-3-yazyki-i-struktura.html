Пять языков стандарта IEC 61131-3

Стандарт IEC 61131-3 (в России ГОСТ Р МЭК 61131-3) описывает пять языков программирования контроллеров. Придумали его не для разнообразия, а чтобы прекратить хаос: до стандарта каждый производитель делал свой язык, и программист, знавший Siemens, не мог прочитать программу Allen-Bradley.

Главное, что нужно понять сразу: это не пять разных инструментов для пяти разных задач. Это пять способов записать одно и то же. Внутри контроллера всё равно выполняется машинный код, и логику «мотор работает, если нажат пуск и не нажат стоп» можно записать любым из них.

Что представляет собой каждый язык

ЯзыкТипСильная сторонаГде встретишь
LADграфическийНаглядность, привычен электрику, легко отлаживать вживуюДискретная логика, 70 % программ на объектах
FBDграфическийХорош для аналоговой обработки и цепочек блоковРегулирование, обработка сигналов
STтекстовыйРасчёты, циклы, работа с массивами и строкамиМатематика, рецепты, обмен данными
SFCграфическийОписание последовательности шагов машиныЦиклические машины, упаковка, розлив
ILтекстовыйПрактически не используется, объявлен устаревшимСтарые проекты, наследие

IL (Instruction List) — это ассемблер для ПЛК, список коротких команд. В новых версиях стандарта он признан устаревшим, и учить его смысла нет. У Siemens есть родственник — STL, который встречается в старых программах S7-300/400. Если увидишь на объекте — просто знай, что это такое.

С чего начинать именно тебе

Учитывая, что ты пришёл из электрики и работаешь на объектах, где стоит Siemens, порядок такой:

  1. LAD — основной язык. Он ближе всего к тому, что ты уже умеешь, и им написано большинство программ, которые ты увидишь на линиях. Второй том целиком про него.
  2. FBD — по мере надобности. Осваивается за вечер, если знаешь LAD. Нужен, когда пойдёт аналоговая обработка и регулирование.
  3. ST — обязательно, но позже. Как только логика перерастёт кнопки и появятся расчёты, масштабирование, обработка массивов — LAD станет громоздким. Тогда ST экономит часы.
  4. SFC — по ситуации. Полезен, если работаешь с машинами, у которых явный цикл: захват, перемещение, отпускание, возврат.
Практика объектов Реальные проекты обычно смешанные. Дискретная логика и блокировки — на LAD, потому что наладчику ночью на линии проще смотреть, где «не проходит ток». Обработка аналоговых сигналов и математика — на ST или FBD. Стандарт это разрешает: разные блоки одного проекта могут быть написаны на разных языках.

Structured Text: текст вместо контактов

ST похож на Паскаль, а если ты видел любой язык программирования — узнаешь общие черты. Разберём по частям, без предварительных знаний.

Присваивание

Основная операция. Знак присваивания в ST — это :=, двоеточие с равно. Обычное = означает сравнение, и путать их нельзя.

Motor := TRUE; записать в переменную единицу Motor := Pusk AND NOT Stop; записать результат логики Davlenie_bar := Syroe_znachenie / 1728.0; расчёт Каждая строка заканчивается точкой с запятой. Забыл — ошибка компиляции.

Логические операции

Те же, что в предыдущем томе, только словами: AND, OR, NOT, XOR. Скобки работают как в математике и задают порядок.

Puskat := (Rezhim_avto OR Rezhim_ruchnoy) AND Davlenie_OK AND NOT Avariya; Скобки здесь принципиальны: без них AND выполнится раньше OR и условие получится совсем другим.

Условие IF

IF Davlenie < 5.0 THEN Avariya_davlenie := TRUE; Motor := FALSE; END_IF; IF Uroven > 90.0 THEN Nasos := FALSE; ELSIF Uroven < 20.0 THEN Nasos := TRUE; ELSE ; ничего не делаем, состояние сохраняется END_IF;

Конструкция читается дословно: если условие, то делать это, иначе если другое условие — то другое, иначе — остальное. ELSIF пишется слитно, без второго E — частая опечатка новичка.

Выбор CASE

Когда вариантов много, вместо лестницы из IF используют CASE. Это основной инструмент для пошаговых циклов машины.

CASE Shag OF 0: IF Start THEN Shag := 10; END_IF; 10: Zazhim := TRUE; IF Zazhim_konchevik THEN Shag := 20; END_IF; 20: Sverlo_vniz := TRUE; IF Sverlo_nizhniy THEN Shag := 30; END_IF; 30: Sverlo_vniz := FALSE; IF Sverlo_verhniy THEN Shag := 40; END_IF; 40: Zazhim := FALSE; Shag := 0; ELSE Shag := 0; защита от неизвестного состояния END_CASE;

Это полноценный пошаговый автомат на десять строк. На LAD то же самое заняло бы два экрана цепей с Set и Reset. Номера шагов дают с запасом (10, 20, 30), чтобы потом можно было вставить промежуточный шаг 15, ничего не перенумеровывая.

Циклы

Цикл повторяет действие несколько раз. В ПЛК это чаще всего обработка массива: проверить все датчики, сложить все значения, найти максимум.

Summa := 0; FOR i := 1 TO 10 DO Summa := Summa + Temperatura[i]; END_FOR; Srednee := Summa / 10.0;
Цикл в ПЛК — источник главной аварии Помни цикл сканирования из первого тома: программа обязана завершиться за отведённое время. Если написать WHILE, условие которого никогда не станет ложным, сработает сторожевой таймер и CPU уйдёт в STOP, а линия встанет. Поэтому в ПЛК предпочитают FOR с явным числом повторений и избегают WHILE и REPEAT. Если WHILE всё-таки нужен, обязательно добавляй счётчик-предохранитель, который прервёт цикл после разумного числа проходов.

Вызов функциональных блоков

Таймеры и счётчики в ST вызываются как блоки, с указанием экземпляра — об экземплярах подробно в шестой главе.

Taymer_pusk( IN := Zapros_puska, PT := T#5s ); IF Taymer_pusk.Q THEN Konveyer := TRUE; END_IF; Ostatok := Taymer_pusk.ET; сколько уже отсчитано, для панели оператора

Комментарии

(* Классический комментарий стандарта, может занимать несколько строк *) // Однострочный комментарий, поддерживается почти везде
Почему ST стоит выучить, даже если пишешь на LAD Три причины. Первая: расчёты. Масштабирование аналогового сигнала, ПИД, статистика на LAD выглядят чудовищно. Вторая: пошаговые циклы через CASE — самый читаемый способ описать машину. Третья: чужой код. Библиотеки, примеры производителей и готовые блоки почти всегда написаны на ST, и уметь их прочитать нужно, даже если сам пишешь контактами.
Задание 2 Перепиши на ST логику из второго тома: конвейер пускается при нажатии пуска, если давление больше 5 бар и коробка не полна, останавливается по стопу. Используй самоподхват. Подсказка: самоподхват в ST — это когда переменная участвует в собственном условии.

FBD: логика блоками

FBD (Function Block Diagram, функциональные блок-схемы) — это логика, нарисованная прямоугольниками. Сигналы входят слева, выходят справа, блоки соединяются линиями. Если ты видел схемы на микросхемах серии 155 или логические элементы в учебнике электроники — это оно.

Когда FBD удобнее LAD

На чистой дискретной логике LAD и FBD равноценны — дело привычки. Но есть области, где FBD выигрывает заметно:

  • Аналоговая обработка. Цепочка «сырое значение → масштабирование → фильтр → ограничение → ПИД → выход» на FBD выглядит как технологическая схема и читается за секунды. На LAD это будет набор блоков, вставленных в цепи, между которыми теряется связь.
  • Готовые блоки производителя. Библиотечные функции для приводов, весов, температурных регуляторов почти всегда нарисованы как FBD-блоки с десятком входов и выходов.
  • Много входов у одной функции. Блок с восемью входами в FBD — обычное дело, в LAD это восемь контактов подряд, которые не помещаются на экран.
Переключение на лету В TIA Portal один и тот же блок можно переключать между LAD и FBD одной кнопкой — представление меняется, логика остаётся. Это удобно: написал в привычном LAD, посмотрел в FBD, понял структуру. Обратно в LAD переключается не всегда — если в FBD использованы конструкции, не выражаемые контактами, среда откажет.

SFC: пошаговые последовательности

SFC (Sequential Function Chart, последовательные функциональные схемы) описывает не логику, а порядок действий. Это блок-схема цикла машины: сделали шаг, дождались условия, перешли к следующему.

Три составные части

  • Шаг (Step) — состояние машины. Начальный шаг рисуют двойной рамкой.
  • Действие (Action) — что делается, пока машина на этом шаге. Пишется на LAD или ST.
  • Переход (Transition) — условие, при котором происходит переход к следующему шагу.

SFC умеет и ветвления: параллельные ветки, которые выполняются одновременно и сходятся в одной точке, и альтернативные, где выбирается один из путей по условию.

Главное достоинство и главный подвох

Достоинство: при отладке видно, на каком шаге стоит машина. Активный шаг подсвечивается. Когда линия зависла, наладчик за секунду понимает: застряли на шаге 20, ждём нижний концевик, — и идёт проверять именно этот датчик. В LAD-программе на такой поиск уйдут минуты.

Подвох: SFC описывает нормальный ход событий. Аварии, ручной режим, возврат в исходное положение из середины цикла, реакция на аварийный стоп — всё это в схему шагов не укладывается и пишется отдельно. Начинающие часто рисуют красивую последовательность и обнаруживают, что машину невозможно вернуть в исходное состояние после сбоя.

Альтернатива без SFC Ровно ту же логику можно написать через CASE на ST — пример был во второй главе. Многие опытные программисты так и делают: меньше зависимости от среды, легче переносить между платформами, а подсветку активного шага заменяет обычный просмотр переменной с номером шага. Если выбираешь между «разбираться с SFC» и «освоить CASE», второе универсальнее.

Целые и дробные: где ловушка

Самая частая ошибка новичка — деление целых чисел. Если обе переменные типа INT, результат тоже будет INT, и дробная часть просто отбросится.

INT: 7 / 2 = 3 дробная часть потеряна безвозвратно REAL: 7.0 / 2.0 = 3.5 правильно Поэтому при масштабировании аналогового сигнала: Davlenie := INT_TO_REAL(Syroe) / 27648.0 * 16.0; Сначала преобразуем в REAL, потом делим. Не наоборот.

И обратная сторона: REAL хранит числа приблизительно. Сравнивать дробные числа на точное равенство нельзя — IF Temperatura = 25.0 может не сработать никогда. Сравнивай через больше-меньше или задавай допуск.

Массивы

Массив — это пронумерованный набор переменных одного типа. Удобно, когда объектов много и они однотипные: двадцать датчиков, десять уставок, история измерений.

Temperatura : ARRAY[1..10] OF REAL; Temperatura[1] := 23.5; Temperatura[7] := 24.1; FOR i := 1 TO 10 DO IF Temperatura[i] > Maks THEN Maks := Temperatura[i]; END_IF; END_FOR;
Выход за границы массива Обращение к Temperatura[15] в массиве на 10 элементов — тяжёлая ошибка. В лучшем случае среда поймает её при компиляции, в худшем контроллер уйдёт в STOP уже на объекте. Если индекс вычисляется в программе, а не задан константой, обязательно проверяй его границы перед обращением.

Структуры

Структура объединяет разнотипные переменные, описывающие один объект. Это то, что превращает программу из свалки тегов в понятную модель оборудования.

TYPE tKonveyer : STRUCT Rabotaet : BOOL; Avariya : BOOL; Skorost : REAL; Schet_yashikov : DINT; Narabotka : TIME; END_STRUCT END_TYPE Konveyer_1 : tKonveyer; Konveyer_2 : tKonveyer; IF Konveyer_1.Avariya THEN Konveyer_1.Rabotaet := FALSE; END_IF;

Описал один раз — используешь для всех однотипных механизмов. Добавил новое поле в структуру — оно появилось у всех конвейеров сразу.

Правила именования

  • Имя должно говорить, что это: KM1_Konveyer, а не M12
  • Держи связь с электрической схемой: если в схеме KM1, то и тег KM1
  • Для булевых переменных имя-утверждение: Davlenie_OK читается как условие
  • Единицы измерения в имени: Davlenie_bar, Vremya_ms — избавляет от половины ошибок в расчётах
  • Латиница без диакритики: кириллица и польские знаки в именах поддерживаются не везде и создают проблемы при переносе проекта
Задание 5 Сырое значение с датчика давления равно 13824, модуль Siemens (диапазон 0…27648), датчик на 0–16 бар. Напиши расчёт на ST правильно, с преобразованием типов. Какой тип будет у результата и почему нельзя обойтись INT?

Блоки Siemens: OB, FB, FC, DB

Программа контроллера не пишется одной сплошной портянкой. Она делится на блоки, и у каждого типа блока своя роль. Это место, где новички путаются чаще всего, поэтому разберём медленно.

OB — организационные блоки

Это точки, через которые операционная система контроллера запускает твою программу. Ты их не вызываешь — их вызывает CPU при наступлении события.

БлокКогда вызывается
OB1 (Main)Каждый цикл сканирования. Основная программа
OB100 (Startup)Один раз при переходе в RUN. Начальная инициализация
OB35 / Cyclic interruptСтрого по времени, например каждые 100 мс. Для регулирования
OB40 / Hardware interruptПо аппаратному событию, минуя цикл. Для быстрой реакции
OB82, OB121 и другиеПри ошибках: отказ модуля, ошибка программирования

Блоки ошибок стоит завести даже в простом проекте. Если их нет, ошибка вроде выхода за границы массива останавливает CPU. Если OB ошибки существует — контроллер вызовет его и продолжит работу, а ты сможешь записать причину и выдать сообщение оператору.

FC — функция без памяти

Получила данные на вход, посчитала, выдала результат и всё забыла. Ничего между вызовами не хранит. Годится для расчётов: пересчёт единиц, масштабирование, проверка условия.

FB — функциональный блок с памятью

Главное отличие: у FB есть статические переменные, которые сохраняются между циклами. Именно поэтому таймеры и счётчики сделаны как FB — им нужно помнить, сколько уже насчитано.

Память FB хранится в отдельном блоке данных — экземплярном DB (Instance DB). И вот тут ключевая идея, ради которой всё это устроено.

Экземпляры: одна программа, много механизмов

Представь линию с пятью одинаковыми конвейерами. Логика у всех одна: пуск, стоп, самоподхват, счёт, авария. Писать пять раз одно и то же — это пять мест для ошибки и пять мест для правки.

Вместо этого пишут один FB с логикой конвейера и вызывают его пять раз, каждый со своим экземплярным DB. Логика общая, а память у каждого своя: свой счётчик, свой таймер, своё состояние.

FB "Konveyer" — написан один раз Вызовы в OB1: "Konveyer_1_DB" ( Pusk := I0.0, Stop := I0.1, Motor => Q0.0 ); "Konveyer_2_DB" ( Pusk := I0.2, Stop := I0.3, Motor => Q0.1 ); "Konveyer_3_DB" ( Pusk := I0.4, Stop := I0.5, Motor => Q0.2 ); Нашёл ошибку — правишь в одном месте, исправляется у всех трёх.

Это самый важный приём во всём томе. Он превращает программу из набора копий в модель оборудования и экономит недели на больших проектах.

DB — блоки данных

  • Global DB — общее хранилище. Уставки, рецепты, данные для панели оператора, счётчики выработки. Доступен из любого блока.
  • Instance DB — память конкретного экземпляра FB. Создаётся автоматически при вызове.

То же самое в CODESYS

CODESYS — среда, не привязанная к одному производителю. Её ставят внутрь своих контроллеров WAGO, ifm, Turck, Beckhoff (там она называется TwinCAT), ОВЕН и десятки других. Логика та же, что у Siemens, но названия другие — и это единственное, что сбивает при переходе.

Задачи вместо организационных блоков

У Siemens программа вызывается из OB1, и период определяется циклом сканирования. В CODESYS есть менеджер задач, где ты сам создаёшь задачи и назначаешь им период и приоритет.

MainTask — циклическая, 20 мс, приоритет 10 -> PLC_PRG FastTask — циклическая, 5 мс, приоритет 1 -> Regulirovanie SlowTask — циклическая, 500 мс, приоритет 20 -> Statistika, Obmen

Это гибче: быстрое регулирование получает свою задачу с высоким приоритетом, а сбор статистики и обмен по сети — медленную. У Siemens то же делается через OB циклических прерываний.

Объявление переменных

PROGRAM PLC_PRG VAR Konveyer_1 : FB_Konveyer; экземпляр блока Taymer : TON; Schet : INT; Davlenie : REAL; END_VAR VAR RETAIN Narabotka : DINT; переживёт отключение питания END_VAR Konveyer_1( Pusk := xPusk, Stop := xStop, Motor => qMotor );

Экземпляр FB объявляется как обычная переменная типа этого блока. Отдельные DB создавать не надо — среда делает это сама. По смыслу это ровно то же, что экземплярный DB у Siemens, просто оформлено проще.

ОВЕН и российские контроллеры

ОВЕН строит свои ПЛК на CODESYS: серия ПЛК1xx работала на CODESYS 2.3, более новые ПЛК2xx — на CODESYS 3.5. Среда скачивается с сайта производителя вместе с пакетом поддержки устройств. Языки и структура проекта стандартные, поэтому знание CODESYS переносится на ОВЕН и обратно без переучивания.

Что это значит практически Выучив Siemens, ты закрываешь автопром и почти всю европейскую промышленность — то, с чем работаешь на объектах сейчас. Выучив CODESYS, получаешь доступ к десяткам производителей и бесплатную среду для домашней практики. Переход между ними занимает пару вечеров, потому что стандарт один. Оптимальный путь: рабочий инструмент — Siemens, домашний полигон — CODESYS.

Как начать без железа

Самая практичная глава тома. Учиться можно вообще без контроллера: программа проверяется в симуляторе, а вместо реального оборудования подключается трёхмерная модель линии.

Вариант 1: TIA Portal + PLCSIM

То, что реально стоит на объектах, где ты работаешь, — поэтому вариант основной.

  • Что скачивать: STEP 7 Basic или Professional. Basic поддерживает только S7-1200, Professional — ещё и S7-1500. Установщик разбит на несколько образов, суммарно десятки гигабайт.
  • Лицензия: пробная на 21 день. Отсчёт начинается с момента установки, а не с первого запуска. Лицензия привязывается к оборудованию компьютера, поэтому переустановка системы нового срока не даёт.
  • Версии: примерно одна крупная версия в год. V20 вышла в декабре 2024, V21 — в декабре 2025. На каждую версию даётся отдельная пробная лицензия: истёк срок у одной — можно поставить следующую и получить новые 21 день.
  • Совместимость проектов односторонняя. Новая версия откроет старый проект, старая новый — нет. Если у заказчика V18, а ты пишешь в V21, вернуть проект обратно не получится. Версию заказчика выясняй до начала работы.
  • PLCSIM — симулятор контроллера, скачивается отдельным файлом и входит в пробную лицензию. Обычного PLCSIM достаточно для учёбы на S7-1200/1500. PLCSIM Advanced — отдельный платный продукт для связи с внешними симуляторами и виртуальной пусконаладки.
  • Подводный камень: загрузка PLCSIM подпадает под немецкие правила экспортного контроля. На аккаунте Siemens может потребоваться дополнительная проверка, занимающая от нескольких часов до пары суток. Запрашивай доступ заранее, а не в тот вечер, когда сел учиться.

Требования к компьютеру: Windows 10 или 11, 64 бита, минимум 8 ГБ памяти (комфортно от 16), процессор уровня Core i5, около 50 ГБ на диске и обязательно SSD — на жёстком диске среда работает мучительно медленно.

Совет по установке Ставь TIA Portal в виртуальную машину. Причин три: среда тянет за собой множество служб, постоянно висящих в системе; при истечении пробного периода машину можно откатить к снимку; на объектах часто нужна конкретная старая версия, и держать несколько версий в отдельных виртуалках спокойнее, чем ставить их рядом в один Windows.

Вариант 2: CODESYS со встроенной симуляцией

  • Среда разработки CODESYS бесплатна. Скачивается из CODESYS Store после регистрации. Актуальная ветка — V3.5, обновляется сервис-паками.
  • Симуляция встроена: включаешь режим Simulation, и программа выполняется прямо в среде без дополнительного софта.
  • В комплекте демонстрационный программный контроллер Control Win SL. Без лицензии он работает по два часа, потом останавливается — перезапустил и продолжил. Для учёбы не мешает.
  • Платить нужно только за рабочие среды исполнения на реальном железе и профессиональные расширения.

Вариант 3: модель объекта Factory I/O

Программа с трёхмерными сценами: конвейеры, сортировщики, лифты, наполнители, паллетайзеры. Собираешь сцену, подключаешь к PLCSIM или CODESYS и видишь, как программа управляет механизмами — включая последствия своих ошибок.

Продукт платный, но даёт пробный период 30 дней с полным набором сцен. Этого хватает на основные учебные задачи. С Siemens связывается напрямую через PLCSIM, с CODESYS — через OPC.

Первый проект: конвейер как блок

Соберём конвейер из второго тома как переиспользуемый функциональный блок. Это тот самый переход от набора цепей к модели оборудования.

Интерфейс блока

FUNCTION_BLOCK FB_Konveyer VAR_INPUT Pusk : BOOL; кнопка пуска Stop : BOOL; кнопка стопа, в поле NC -> здесь 1 = норма Datchik : BOOL; датчик наличия ящика Sbros : BOOL; кнопка «Готово» Davlenie_bar : REAL; давление в пневмосети Norma_yashikov : INT; сколько ящиков в коробку END_VAR VAR_OUTPUT Motor : BOOL; контактор конвейера Lampa_rabota : BOOL; Lampa_korobka : BOOL; Sirena : BOOL; Avariya : BOOL; Schet : INT; текущий счёт, для панели оператора END_VAR VAR Zapros : BOOL; внутреннее состояние Davlenie_OK : BOOL; Korobka_polna : BOOL; Taymer_predupr : TON; экземпляры блоков — Front_datchik : R_TRIG; у каждого своя память Front_sbros : R_TRIG; END_VAR

Тело блока

// 1. Условия Davlenie_OK := Davlenie_bar > 5.0; // 2. Запрос на пуск с самоподхватом Zapros := (Pusk OR Zapros) AND Stop AND Davlenie_OK AND NOT Korobka_polna AND NOT Avariya; // 3. Предупредительный сигнал 5 секунд Taymer_predupr( IN := Zapros, PT := T#5s ); Sirena := Zapros AND NOT Taymer_predupr.Q; // 4. Движение Motor := Zapros AND Taymer_predupr.Q; Lampa_rabota := Motor;
// 5. Счёт ящиков по фронту Front_datchik( CLK := Datchik ); IF Front_datchik.Q AND Motor THEN Schet := Schet + 1; END_IF; IF Schet >= Norma_yashikov THEN Korobka_polna := TRUE; END_IF; // 6. Сброс счёта по кнопке Front_sbros( CLK := Sbros ); IF Front_sbros.Q THEN Schet := 0; Korobka_polna := FALSE; END_IF; Lampa_korobka := Korobka_polna; // 7. Авария по давлению: взводится, снимается только при возврате нормы IF Motor AND NOT Davlenie_OK THEN Avariya := TRUE; END_IF; IF Front_sbros.Q AND Davlenie_OK THEN Avariya := FALSE; END_IF;

Разбор ключевых мест

Самоподхват в ST. Строка Zapros := (Pusk OR Zapros) AND ... — это тот же блок-контакт, только записанный текстом. Переменная участвует в вычислении собственного значения: если она уже была единицей, условие остаётся истинным без нажатой кнопки. Приоритет стопа сохранён: AND Stop стоит снаружи скобок и рвёт условие безусловно.

Порядок строк. Он важен так же, как порядок сетей в LAD. Таймер вызывается после вычисления Zapros, чтобы получить актуальное значение в этом же цикле. Если поменять местами, реакция задержится на цикл.

Условие AND Motor при счёте. Без него счётчик будет считать ящики, которые кто-то проносит мимо датчика рукой при остановленном конвейере. Мелочь, но именно из таких мелочей состоит разница между программой «работает на стенде» и «работает на объекте».

Вызов блока для трёх линий

Konveyer_1( Pusk := "S1_Pusk_L1", Stop := "S2_Stop_L1", Datchik := "B1_L1", Sbros := "S3_Gotovo_L1", Davlenie_bar := Davlenie_seti, Norma_yashikov := 20, Motor => "KM1_L1", Lampa_rabota => "HL1_L1" ); Konveyer_2( Pusk := "S1_Pusk_L2", ... Norma_yashikov := 12, ... ); Konveyer_3( Pusk := "S1_Pusk_L3", ... Norma_yashikov := 24, ... );

Три линии, разные нормы упаковки, разные входы и выходы — одна логика. Нашёл ошибку или добавил функцию — правишь в одном месте, работает у всех трёх. Именно за это в проектах и держатся структуры и функциональные блоки.

Мысль напоследок Языки и блоки — это инструменты организации, а не сама автоматизация. Программа из одного блока на две тысячи строк и программа из тридцати аккуратных FB делают одно и то же, но первую невозможно поддерживать, а вторую наладчик разберёт за вечер. Разница между новичком и профессионалом видна не в знании синтаксиса, а в том, как поделена программа.
